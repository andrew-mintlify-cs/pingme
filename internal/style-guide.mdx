Use the smallest component that does the job. Plain Markdown first; a component only when it changes how a reader moves through the page.

## Callouts

One callout per section at most. If a page needs three warnings, the page is the problem.

<Note>
  **Note** — neutral context the reader can skip. *"Test keys never deliver to real recipients."*
</Note>

<Tip>
  **Tip** — a better way to do the thing they are already doing. *"Store your user ID in `external_id` so you can skip the lookup table."*
</Tip>

<Info>
  **Info** — a fact about scope or version. *"This guide uses API v2."*
</Info>

<Warning>
  **Warning** — something that costs money, data, or a live send if ignored. *"Never embed a live key in a mobile app."*
</Warning>

<Check>
  **Check** — confirmation that a step or the whole task worked. *"Deliveries move to `delivered` within a few seconds."*
</Check>

## Steps

For ordered procedures where the reader does something at each step. Three to seven steps; if you have more, split the page.

<Steps>
  <Step title="Create a recipient">
    One action per step, with the code that performs it directly beneath.

    ```bash
    curl https://api.pingme.dev/v2/recipients -H "Authorization: Bearer $PINGME_API_KEY" -d '{"email": "priya@acme-analytics.example"}'
    ```
  </Step>
  <Step title="Send a message">
    Tell the reader what to expect in the response so they know the step worked.
  </Step>
  <Step title="Check delivery">
    End with the verification, not with the last mutation.
  </Step>
</Steps>

## Code groups

The same example in several languages. The reader picks a tab once and the choice sticks across the site.

<CodeGroup>
```bash curl
curl https://api.pingme.dev/v2/messages \
  -H "Authorization: Bearer $PINGME_API_KEY" \
  -d '{ "recipient_id": "rcp_01J8X4K2M9", "channels": ["email"], "template_id": "tpl_welcome_v3" }'
```

```python Python
requests.post(f"{API}/messages", headers=HEADERS, json={
    "recipient_id": "rcp_01J8X4K2M9",
    "channels": ["email"],
    "template_id": "tpl_welcome_v3",
})
```

```typescript TypeScript
await fetch(`${API}/messages`, {
  method: "POST",
  headers,
  body: JSON.stringify({ recipient_id: "rcp_01J8X4K2M9", channels: ["email"], template_id: "tpl_welcome_v3" }),
});
```
</CodeGroup>

## Tabs

For prose that differs by platform, role, or scenario — not for code (use a code group). The reader already knows which tab applies to them.

<Tabs>
  <Tab title="Happy path">
    Your app calls PingMe, PingMe renders the template, each channel goes to its provider, and `message.delivered` events flow back to your webhook.
  </Tab>
  <Tab title="Channel fails">
    PingMe retries transient errors, marks the channel `failed` with the provider's reason, and fires `message.failed` so you can fall back.
  </Tab>
  <Tab title="User opts out">
    Future sends on that channel are silently skipped, and `recipient.unsubscribed` lets you mirror the preference.
  </Tab>
</Tabs>

## Accordions

Progressive disclosure for detail most readers do not need: FAQs, edge cases, long error tables.

<AccordionGroup>
  <Accordion title="What happens if a channel fails?">
    PingMe retries transient failures automatically. If a channel ultimately fails, the message's aggregate status becomes `partially_delivered` or `failed` and a `message.failed` webhook fires.
  </Accordion>
  <Accordion title="Is there a sandbox?">
    Yes. Test API keys (`pm_test_…`) exercise the full API but never deliver to real recipients.
  </Accordion>
  <Accordion title="Can I cancel a scheduled message?">
    Until it sends. `POST /messages/{id}/cancel` returns `409` once the message has been handed to a provider.
  </Accordion>
</AccordionGroup>

## Tables

Plain Markdown tables for anything compared against consistent attributes. Left-align text, keep to five columns or fewer.

| Component | Reach for it when | Avoid it when |
| :-- | :-- | :-- |
| Callout | One sentence must not be missed | Every paragraph feels important |
| Steps | The reader acts at each step | The list is just facts in order |
| Code group | Same example, several languages | Examples differ in what they do |
| Tabs | Prose differs by scenario | The content is code |
| Accordion | Detail most readers skip | The content is required to proceed |
| Card | Sending the reader somewhere | Explaining something in place |
