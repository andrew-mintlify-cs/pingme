Each section below shows one component, the rule for using it, and a live example with real PingMe content.

## Callouts

Five callouts, five different signals. Use at most one or two per screen — if every paragraph has a callout, none of them stand out.

<Note>
  **Note** — context that helps but is not required. Test keys (`pm_test_…`) appear in your logs tagged **Test**.
</Note>

<Tip>
  **Tip** — a shortcut or best practice. Build your `Idempotency-Key` from your own user ID so retries never send a duplicate.
</Tip>

<Info>
  **Info** — neutral background. Sends are asynchronous: the response returns `202 Accepted` with `status: queued`.
</Info>

<Warning>
  **Warning** — something that will cost the reader if ignored. The webhook signing `secret` is shown once. Store it before you leave the page.
</Warning>

<Check>
  **Check** — confirmation that a step worked. Deliveries move to `delivered` within a few seconds in the sandbox.
</Check>

## Steps

Use `Steps` for procedures the reader performs in order. Each step gets a verb-first title and, where possible, a way to verify it worked.

<Steps>
  <Step title="Create a recipient">
    Store your user's ID in `external_id` so you can find them later without a lookup table.
  </Step>
  <Step title="Send a message">
    Reference a template or pass inline `content`. The response includes a `msg_` ID.
  </Step>
  <Step title="Confirm delivery">
    Poll `GET /messages/{id}/deliveries` or subscribe to the `message.delivered` webhook.
  </Step>
</Steps>

Use `CodeGroup` when the same example exists in more than one language. Write the explanation once; the reader picks their tab.

## Tabs

Use `Tabs` when the reader already knows which variant applies to them — a platform, a role, a plan. Unlike `CodeGroup`, tabs hold prose and components, not just code.

<Tabs>
  <Tab title="Email">
    Delivered through PingMe's email gateway. Includes an unsubscribe link automatically.
  </Tab>
  <Tab title="SMS">
    Carrier delivery receipts drive the `delivered` status. STOP replies set the recipient's `sms` preference to `false`.
  </Tab>
  <Tab title="Push">
    Requires a device token registered on the recipient. Invalid tokens fail with `device_token_invalid`.
  </Tab>
</Tabs>

## Accordions

Use `Accordion` for detail most readers can skip — FAQs, edge cases, long error tables. The title must make sense on its own, because that is all most readers see.

<AccordionGroup>
  <Accordion title="What happens if a channel fails?">
    PingMe retries transient failures automatically. If the channel ultimately fails, the message becomes `partially_delivered` or `failed` and a `message.failed` event fires.
  </Accordion>
  <Accordion title="Can I cancel a scheduled message?">
    Yes, until it sends. `POST /messages/{id}/cancel` returns `409` once the message has left the `scheduled` state.
  </Accordion>
</AccordionGroup>

## Tables

Use a Markdown table when you are comparing several items against the same attributes. Keep cells short; if a cell needs a paragraph, the content wants an accordion instead.

| :-- | :-- | :-- | :-- |

## House rules

- One idea per callout, one callout per idea.
- Steps for procedures; numbered Markdown lists for things that are ordered but not performed.
- Every code sample must run as written with only `PINGME_API_KEY` set.
- Internal links are root-relative: `/v2/api-keys`, never the full domain.
